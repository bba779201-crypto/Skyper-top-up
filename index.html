Admin login returns 401 right after deploy Did you run the seed on the production database? Connect locally with your prod `DATABASE_URL` and run `npm run db:seed` once.
Admin login shows "JWT_SECRET must be set and at least 32 characters" Set `JWT_SECRET` in Vercel and make it at least 32 characters, then redeploy.
Build/runtime error: "The table public.Settings does not exist" Your DB is connected but schema is not initialized. Run: ```bash npx prisma db push npm run db:seed ``` against the same `DATABASE_URL` used by Vercel.
KHPay QR expired / webhook never fires - The QR is **valid for 180 seconds** — this is a KHPay limit, not a bug. - Webhook URL in KHPay dashboard must be `https://your-domain/api/payment/webhook/khpay` (HTTPS, not localhost). - For local testing use a tunnel: `cloudflared tunnel --url http://localhost:3000` and set `PUBLIC_APP_URL` to the tunnel URL. - If the webhook doesn't reach you, the order-detail page auto-polls KHPay every 3 seconds — the order will still flip to PAID.
Checkout redirects to localhost in production Set both `NEXT_PUBLIC_BASE_URL` and `PUBLIC_APP_URL` to your live domain (no trailing slash), then redeploy.
Free Fire UID check says "Couldn't verify" Nickname lookup depends on a third-party validation API and can fail intermittently. Checkout still works; users can continue payment.
Prisma error on Vercel: "Can't reach database" - You're still on SQLite. Switch `provider` to `postgresql` in `prisma/schema.prisma` and push. - Or your `DATABASE_URL` is wrong. For Neon/Supabase, make sure it ends with `?sslmode=require`.
PDF invoice returns 500 on Vercel - Already handled: [`next.config.js`](next.config.js) declares `pdfkit` as `serverComponentsExternalPackages` and the route is pinned to `runtime = "nodejs"`. If it still happens, redeploy after clearing Vercel's build cache.
Uploaded images disappear on Vercel `public/uploads/` is **read-only** on Vercel. Wire any upload feature to Vercel Blob / Cloudinary / S3 instead of the filesystem.

Authentication & Authorization - Keep JWT secrets, payment API keys, webhook secrets, DB credentials, and bot tokens in environment variables only. - Use 64+ character random production secrets and rotate them after suspected exposure. - Admin sessions use HttpOnly/Secure/SameSite cookies. Add MFA and separate superadmin/break-glass accounts. - Protect every `/api/admin/*` route server-side and enforce role checks for destructive/financial actions. - Use bcrypt or Argon2 password hashes. Never store plaintext passwords or API keys. - Rate-limit login attempts and return generic credential errors. ## 2. Payment & Transaction Security - The payment provider is the source of truth. Never trust a browser success page to mark an order paid. - Verify webhook HMAC signatures against the raw body before parsing/processing. - Validate transaction ID, order number, amount, currency, event type, and expected order state. - Make webhook handling idempotent and use conditional DB state transitions to prevent double fulfillment. - Persist verified payment state before calling fulfillment. - Disable simulation in production and keep gateway credentials server-side. ## 3. API & Rate Limiting - Rate-limit admin login, order creation, UID lookup, promo validation, invoice generation, and admin mutations. - The included in-memory limiter is suitable for single-process development only. Use shared Redis/Upstash in serverless production. - Put Cloudflare or an equivalent WAF/CDN in front of the app for DDoS and bot protection. - Validate input with strict Zod schemas, cap body size, and reject malformed/oversized requests. - Never trust client-provided price, discount, role, payment status, or fulfillment status. ## 4. Database & Data Protection - Prisma queries are parameterized. Never concatenate user input into SQL; parameterize any required raw SQL. - Avoid `dangerouslySetInnerHTML` for untrusted content. Sanitize HTML if HTML is required. - Use a restrictive Content Security Policy and output encoding to reduce XSS impact. - Encrypt highly sensitive data at rest when it does not need plaintext querying; use TLS for DB connections. - Use least-privilege DB credentials, encrypted backups, and tested restore procedures. - Minimize retention of personal/technical data and never log passwords, secrets, or raw session tokens. ## 5. Server & Infrastructure - HTTPS everywhere; redirect HTTP to HTTPS. Enable HSTS after confirming all required subdomains support HTTPS. - Patch Node.js, Next.js, Prisma, OS packages, and dependencies regularly. - Configure WAF managed rules, bot protection, rate limits, and DDoS protection. - VPS hardening: disable unused services/ports, use SSH keys, restrict DB access, and run processes with least privilege. - Skyper includes baseline CSP, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, and Permissions-Policy headers. - Monitor failed logins, invalid webhook signatures, payment failures, unusual order velocity, and privileged admin changes. ## Production checklist - [ ] Strong `JWT_SECRET` - [ ] Strong `KHPAY_WEBHOOK_SECRET` - [ ] `PAYMENT_SIMULATION_MODE=false` - [ ] HTTPS production URLs - [ ] WAF/CDN configured - [ ] Shared production rate limiter - [ ] PostgreSQL backups + restore test - [ ] Admin MFA - [ ] Audit logs monitored - [ ] Dependency advisories reviewed - [ ] CSP reviewed after adding external scripts/widgets - [ ] Penetration test completed before significant production funds ## Incident response 1. Rotate/revoke exposed secrets immediately. 2. Review logs and audit records. 3. Reconcile payment-provider transactions against order records. 4. Disable compromised admin accounts/sessions. 5.
